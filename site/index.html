Problem & approach

One camera, one intersection, unknown test videos from the same mount. The pipeline decodes every 3rd frame, aligns each recording onto a reference frame, tracks road users, and turns trajectories plus hand-measured scene geometry into events. Learned components do perception; rules do the reasoning, so every event can be explained.

ComponentLearned or rule-based
Road-user detection & trackingLearned: YOLO11n (COCO) + BoT-SORT
Camera alignment across recordingsClassical: ORB features, RANSAC similarity
Metric calibrationFitted pinhole camera (≈12k pedestrian heights, lane vanishing point, 14 m stop line)
Traffic-light colourClassical: HSV + lamp position
14 event classesRules on trajectories, geometry and light state
Accident / near-miss / obstacle / fire confirmationLearned: Qwen3-VL-2B-Instruct verifier, P(yes) from next-token logits, ≤ 30 calls per video

Report

What worked

  • Checking every rule on real frames, not only on synthetic tests: it caught the pedestrian-vs-vehicle signal mix-up, riders counted as pedestrians, people waiting on the kerb, and red-to-green line creeping.
  • Traffic-light state from an absolute lit-pixel count plus lamp position: clean ~33 s red / ~36 s green cycles on all four videos, day and dusk.
  • Runtime alignment (4-DOF similarity): the same geometry lands on the zebras in every recording.
  • Metric calibration from pedestrian heights: two independent scale cues (people at 1.7 m and a 4-lane stop line) agree within 3 %.
  • A Qwen3-VL-2B verifier that answers yes/no from logits: 0 of 98 false accident / near-miss / obstacle candidates accepted.
  • Runtime well inside the 3× limit on an Apple M4 (see Results).

What did not (yet)

  • No ground truth: thresholds are tuned by eye, so precision and recall are not measured.
  • The VLM verifier rejected all 98 false candidates on the samples, but its recall is untested: the samples contain no accident. Fire/smoke stays disabled.
  • The tracker switches IDs at 10 fps (≈1,200 tracks in 340 s), which shortens trajectories.
  • Not yet timed on the evaluation GPU (T4).
  • Part B has no accident examples to calibrate on; it is a physics baseline, not a trained model.
